What we learned

The codes are sound

Every table that was run is reproduced at the precision the thesis claims. Three saved outputs from 2018–2019 are reproduced bit for bit by today's build.

Lost inputs can be rebuilt

The echelette, pyramid and circular-hole profiles were lost. tools/mkprofile.py regenerates them from their analytic description, and each one was checked against a saved result.

RCWA is not lost

calcul_method = Z_INVAR treats every slice as z-invariant. With 1000 slices it reproduces the thesis RCWA column to every printed digit.

Slices are the integration steps

md2D takes one RK4 step per S-matrix slice, and delta_h is read but never used. A thesis run with "5000 steps" needs NS = 5000 today. Metals in TM need at least 1000.

Parameter-file traps

fft_filter and delta_h are required. smoothing used to be left uninitialised when missing; it now defaults to 0.

Two thesis errata

The conical-incidence table (3.1) was computed with h = 1λ and φ = 45°, not the caption's 0.1λ and 30°. The biperiodic sine (4.5) uses h = 0.1 period, not 0.1λ.

Normal vectors in 3D

For surface profiles (H_XY) md3D computes the normal field itself, so no separate file is needed. For index maps (N_XY_ZINVAR) the normal is hard-coded as radial, and the code that reads a normal file is never reached.

3D cost limits the check

Cost grows roughly as (2N+1)⁶. With reference BLAS the pyramid took 22 min at N = 9 on a shared machine, so the thesis's N = 15 points were not reached.
